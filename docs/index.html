Seu Linux vira um template.
Seus dados ficam com você.

O maloki transforma o sistema que está rodando numa imagem .qcow2 portátil, sem /home, sem senhas de Wi‑Fi, sem chaves, com os usuários que você escolher.

Três comandos. Uma imagem.

Você responde algumas perguntas (ou passa um arquivo) e o maloki faz o resto, mostrando cada comando que executa.

O que acontece por dentro

O maloki é um maestro: ele conduz as ferramentas que o Linux já tem, na ordem certa, e limpa tudo se algo der errado no caminho.

Cria o disco virtuallosetup faz um arquivo virar o disco /dev/loop0
Particiona e formataBIOS boot, EFI, /boot e raiz: liga em qualquer firmware
Copia o sistemarsync sem dados pessoais; bancos de dados pausados
Remove o que é seuWi‑Fi, VPN, chaves, machine-id, logs, histórico
Prepara o chrootPara rodar comandos "dentro" da imagem
Ajusta boot e redeGRUB, initramfs com drivers de VM, IP fixo vira DHCP
Troca os usuáriosRemove os seus e cria os que você escolheu
Gera o .qcow2qemu-img convert, compactado se você quiser
Confereqemu-img check na imagem pronta

O que vai e o que fica de fora

A regra: o que faz o sistema funcionar vai; o que é seu ou identifica esta máquina fica de fora.

✅ Vai para a imagem

  • Programas instalados (e Flatpaks, se quiser)
  • Configurações do sistema em /etc
  • Serviços e o que eles precisam
  • Kernel, com o boot ajustado para VMs
  • Os usuários que você criar

🚫 Fica de fora

  • /home, /root e o seu usuário
  • Senhas de Wi‑Fi e VPN
  • Chaves SSH do servidor e machine-id
  • IP fixo (vira DHCP)
  • Logs, caches, histórico, e‑mails, digitais
  • Discos de VMs e containers

Uso

Três jeitos de rodar, para três momentos diferentes.

Mostra cada comando que seria executado, na ordem, sem executar nenhum. Não precisa de sudo. É o melhor jeito de entender o programa.

maloki --simular

Vá para uma pasta com espaço livre (a imagem é criada ali) e responda as perguntas: nome da imagem, tamanho, hostname, usuários, root, compactação.

cd /media/hd-externo
sudo maloki

Para scripts, cron e Ansible: as respostas vêm de um arquivo TOML e nenhuma pergunta é feita. Use senha_hash para não deixar a senha escrita no arquivo.

imagem = "template.qcow2"
hostname = "web-01"
compactar = true

[[usuarios]]
nome = "maria"
senha_hash = "$6$..."        # openssl passwd -6
admin = true
chave_ssh = "~/.ssh/id_ed25519.pub"
sudo maloki --plano meu-plano.toml

Crie um disco "filho" (overlay) para não alterar o template, e ligue:

qemu-img create -f qcow2 -b template.qcow2 -F qcow2 vm1.qcow2
qemu-system-x86_64 -enable-kvm -m 4G -cpu host \
  -drive file=vm1.qcow2,if=virtio -nic user,hostfwd=tcp::2222-:22
ssh -p 2222 maria@localhost

Para o VirtualBox ou o VMware, converta:

qemu-img convert -O vdi  template.qcow2 template.vdi
qemu-img convert -O vmdk template.qcow2 template.vmdk

Feito para não estragar nada

Ele roda como root e mexe com discos. Por isso cada risco tem uma trava.

🔍

Simulação

Veja todos os comandos antes. Nenhum é executado.

⌨️

Ctrl+C seguro

Cancelou no meio? Desmonta, desconecta, religa os serviços e apaga a imagem incompleta.

💾

Espaço conferido

Se não couber, nada começa. O seu disco nunca enche no meio.

🛡️

Trava de caminho

Só apaga dentro de /mnt/maloki-*. Qualquer outro caminho para tudo.

🔒

Uma execução por vez

Duas cópias juntas poderiam brigar pelo mesmo disco. Não deixamos.

🗄️

Bancos pausados

PostgreSQL, MySQL, Redis, MongoDB param durante a cópia e voltam no fim.

Manual

MALOKI(1)Comandos do UsuárioMALOKI(1)

NOME

maloki — transforma o Linux que está rodando numa imagem QEMU (.qcow2) sem os seus dados pessoais

SINOPSE

sudo maloki
sudo maloki --plano arquivo.toml
maloki --simular [--plano arquivo.toml]
maloki --ajuda

OPÇÕES

--simular
Mostra todos os comandos que seriam executados, sem executar nenhum e sem alterar nada. Não precisa de sudo.
--plano arquivo
Modo automático: lê as respostas de um arquivo TOML. Nenhuma pergunta é feita.
--ajuda, -h, --help
Mostra um resumo do uso e sai.

ARQUIVO DE PLANO

imagem = "template.qcow2"
Obrigatório. Nome do arquivo (relativo à pasta atual) ou caminho absoluto.
tamanho_gb = 40
Tamanho do disco da VM. Padrão: o usado + 30% + 5 GB (mínimo 20).
hostname = "template"
Nome da máquina.
flatpak · compactar · parar_servicos
Padrão true.
sobrescrever
Padrão false.
senha_root · senha_root_hash
Sem nenhum dos dois, o root fica bloqueado (recomendado).
[[usuarios]]
nome, senha ou senha_hash, admin, trocar_senha, chave_ssh. Pelo menos um admin (ou senha de root) é obrigatório.

STATUS DE SAÍDA

0
Imagem criada (ou ajuda exibida).
1
Erro; a mensagem diz o motivo. Nada fica montado nem conectado.
2
Opção inválida na linha de comando.

ARQUIVOS

/run/maloki.lock
Trava contra duas execuções simultâneas.
/mnt/maloki-PID
Onde a imagem fica montada durante a criação.

Perguntas frequentes

Precisa de cloud-init, Docker ou alguma coisa especial?

Não. Precisa de qemu-img, rsync, dosfstools e do GRUB, que o instalador da sua distro já tem. O programa avisa se faltar algo.

# Fedora / Rocky
sudo dnf install qemu-img rsync dosfstools grub2-pc-modules
# Debian / Ubuntu
sudo apt install qemu-utils rsync dosfstools grub-pc-bin grub-efi-amd64-bin
Minhas chaves de HTTPS vão para a imagem?

Sim. Um servidor web pode precisar delas para ligar, então o maloki não apaga, mas lista todas no final para você decidir. Se a imagem for compartilhada, troque essas chaves.

Quanto tempo demora?

Quase tudo é a cópia: um servidor de 3 GB leva poucos minutos; um desktop de 20 GB, de 10 a 20 minutos. Compactar leva outro tanto.

A imagem reiniciou sozinha no primeiro boot. É normal?

Sim, em sistemas com SELinux (Fedora, Rocky...): ela reetiqueta os arquivos e reinicia uma vez.
